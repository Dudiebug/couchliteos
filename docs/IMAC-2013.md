# iMac Late 2013 (`imac2013` build profile)

The `imac2013` profile builds a MoonlightOS image for the Apple iMac Late 2013
with an NVIDIA Kepler GPU (iMac14,2 27-inch or iMac14,3 21.5-inch). It is a
separate ISO; the Intel OptiPlex image is unchanged.

```bash
sudo make build PROFILE=imac2013
# build/out/moonlightos-<version>-imac2013-amd64.iso
```

> Status: the image builds, and boot, launcher, Settings, persistence, and
> Remote Desktop are covered by VM tests. **No test has run on the iMac yet.**
> Record the section 0 report below and every item of the
> [hardware checklist](TESTING.md#imac-late-2013-hardware-checklist) before
> publishing a release.

## Section 0: identify the exact machine

Target unit: Apple serial `DCPM5026FQPG`. The serial is used as an identifier
only; serial decoders are incomplete and do not pin down the build-to-order GPU
or the Wi-Fi chip, so both are confirmed on the hardware.

Boot the ISO (below), open **TERMINAL**, and run:

```bash
sudo moonlightos-hardware-report
```

The report runs the four section 0 commands, checks the results, and saves a
copy under `/var/log/moonlightos/`. You can also run them by hand:

```bash
sudo dmidecode -s system-product-name
sudo dmidecode -s system-serial-number
lspci -nn | grep -iE 'vga|3d|net|audio'
lsusb
```

Expected:

| Check | Expected result |
|---|---|
| Serial number | `DCPM5026FQPG` |
| Model | `iMac14,2` (27-inch; GT 755M, GTX 775M, or GTX 780M) or `iMac14,3` (21.5-inch; GT 750M) |
| GPU | an NVIDIA `[10de:....]` VGA or 3D controller |
| Wi-Fi | Broadcom BCM4360 `[14e4:43a0]` |
| Ethernet | Broadcom BCM57766 `[14e4:1682]` |
| Audio | Intel HDA controller; codec Cirrus Logic CS4208 |

If the model is `iMac14,1`, the machine is the 21.5-inch Intel Iris Pro model
with no NVIDIA GPU. Stop: this profile's GPU assumptions do not apply (Iris Pro
is Haswell and needs the i965 VA-API driver, which neither profile ships yet).
Stop as well if anything else in the table differs.

## What the profile changes

| Component | imac2013 profile |
|---|---|
| GPU: NVIDIA Kepler | In-kernel `nouveau` with Mesa only. The build fails if any proprietary NVIDIA package or module is present, and `nvidia*` modules are blacklisted. Kepler's last proprietary branch (470) has no GBM, which wlroots/Cage require; a driver mismatch caused a black screen on this machine before. KMS stays on: never add `nomodeset`. |
| Video decode | Kepler has no HEVC decoder, and nouveau's H.264 decoder needs firmware that cannot be redistributed. Moonlight defaults to software H.264 at 1080p60. |
| CPU: Haswell quad-core i5/i7 | Debian kernel defaults. |
| Panel: 2560x1440 or 1920x1080 | Cage starts on the panel's preferred (native) mode. Settings → Display marks it `(NATIVE)`. |
| Wi-Fi: Broadcom BCM4360 | `broadcom-sta-dkms` (`wl`). The build installs `linux-headers-amd64` for the image kernel, builds `wl.ko` with DKMS inside the chroot, checks its vermagic, and checks that `wl.ko` exists in the final squashfs. `b43`, `b43legacy`, `bcma`, `ssb`, `brcmsmac`, and `brcm80211` are blacklisted. |
| Ethernet: Broadcom BCM57766 | `tg3` with `tigon/tg357766.bin` from `firmware-misc-nonfree` (checked at build time). |
| Audio: Cirrus Logic CS4208 | `snd-hda-intel` (codec fixups are automatic). |
| Bluetooth: Broadcom | `btusb`; managed in Settings → Bluetooth. |
| Apple keyboard | `options hid_apple fnmode=2`: F1–F12 act as function keys (F12 opens the on-screen keyboard); hold Fn for media keys. |
| Sensors | `applesmc` and `coretemp` load at boot; `lm-sensors` output appears in System Diagnostics. |
| Archive areas | `main contrib non-free non-free-firmware` (both profiles). |
| Firmware | A curated list instead of live-build's install-everything default: `firmware-misc-nonfree`, `firmware-linux-free`, `intel-microcode`, `bluez-firmware`, and firmware for common USB Wi-Fi/Ethernet/Bluetooth adapters (`firmware-realtek`, `-atheros`, `-mediatek`, `-iwlwifi`, `-brcm80211`). No NVIDIA firmware package is installed; the build fails if one appears. |
| Removed | `intel-media-va-driver`, `intel-gpu-tools`, `firmware-intel-graphics`, and the other GPU and server firmware packages. |

The profile lives in `config/profiles/imac2013/`: a package list, the
`0200-imac2013.hook.chroot` build checks, and the modprobe/modules-load files.

## Boot steps

1. Write the ISO to a USB drive in raw/DD mode (for example
   `sudo dd if=moonlightos-<version>-imac2013-amd64.iso of=/dev/sdX bs=4M conv=fsync`,
   Rufus in DD mode, or balenaEtcher).
2. Plug the drive into a rear USB port, connect Ethernet if available, and
   power the iMac on while holding **Option (⌥)**.
3. In the Apple Startup Manager, choose the yellow **EFI Boot** entry. The
   2013 Apple firmware has no UEFI Secure Boot, so nothing needs to be disabled.
4. GRUB starts **Start MoonlightOS** after three seconds. The launcher appears
   at the panel's native resolution.
5. If the screen stays black, reboot and pick **Start MoonlightOS (No
   Persistence)**, then collect `/var/log/moonlightos` and the journal with
   Settings → Generate Support File. Do not add `nomodeset`: Cage needs KMS.

Installing to the internal disk (**Install MoonlightOS**) erases macOS. Late
2013 iMacs may have a Fusion Drive (separate SSD and HDD); choose the target disk
carefully in the installer.

## Wi-Fi

Open Settings → Setup Wizard → Network, or the hidden **NETWORK SETUP**
application, and join the network. Check the driver in System Diagnostics
(`wlp…s0 driver: wl`) or with `lsmod | grep '^wl '`.

On an installed system, a kernel update rebuilds `wl.ko` through DKMS; keep
`linux-headers-amd64`, `dkms`, and `broadcom-sta-dkms` installed. The build
removes the DKMS module-signing key it generates, so the ISO carries no private
key; an installed system generates its own on the next rebuild. Because the
module is unsigned, `wl` loads only with Secure Boot off, which is always the
case on this Apple firmware.

## Moonlight defaults

`/var/lib/moonlightos/config.ini` starts with:

```ini
[moonlight]
resolution = 1920x1080
fps = 60
codec = H.264
decoder = software
```

The launcher passes `--video-codec H.264 --video-decoder software` when it
starts a configured stream, and on first launch seeds Moonlight's own settings
file with 1920x1080, 60 FPS, H.264, and software decoding. After that, changes
made in Moonlight's settings persist; 1440p stays selectable there (on the
27-inch panel it is the native resolution).

## Known limitations

- **Software-only decoding.** Kepler cannot decode HEVC or AV1, and nouveau's
  H.264 decoder needs non-redistributable NVIDIA firmware, so Moonlight decodes
  H.264 on the CPU. 1080p60 is the target; 1440p60 may drop frames on the i5.
- **nouveau clocks.** nouveau does not reclock Kepler automatically; the GPU
  runs at its boot clocks. Compositing a 2560x1440 panel works, but GPU-heavy
  work is slow. The proprietary driver is not an option (no GBM).
- **Wi-Fi** uses Broadcom's proprietary `wl` driver built with DKMS. It needs
  Secure Boot off (always true on this firmware).
- Sleep/resume, display brightness control, fan behavior under sustained load,
  headphone-jack switching, and the FaceTime HD camera are untested.
- Nothing in this document has been verified on the physical iMac yet; see the
  hardware checklist in [TESTING.md](TESTING.md#imac-late-2013-hardware-checklist).
