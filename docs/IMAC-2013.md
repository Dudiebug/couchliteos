# iMac Late 2013

The Apple iMac Late 2013 with an NVIDIA Kepler GPU (iMac14,2 27-inch or
iMac14,3 21.5-inch) runs the **general** ISO, `moonlightos-<version>-amd64.iso`.
Since v0.1.13 there is no separate iMac image: the general ISO detects the
machine at boot and applies the iMac-specific drivers below. The NVIDIA ISO
also works, because the 550 driver does not support Kepler and it falls back
to nouveau, but it only adds size.

The `imac2013` profile that built the v0.1.12 iMac ISO is still buildable as a
legacy profile (`sudo make build PROFILE=imac2013`) for comparison. It is not a
release asset.

> Status (v0.1.13): the general ISO passes the QEMU live, persistence, and
> install tests (see [TESTING.md](TESTING.md)). A VM cannot emulate the Kepler
> GPU, Broadcom Wi-Fi, or CS4208 audio. **No test has run on the iMac yet.**
> Record the section 0 report below and every item of the
> [hardware checklist](TESTING.md#imac-late-2013-hardware-checklist) before
> publishing a release.

## Section 0: identify the exact machine

Target unit: Apple serial `DCPM5026FQPG`. The serial is used as an identifier
only; serial decoders are incomplete and do not pin down the build-to-order GPU
or the Wi-Fi chip, so both are confirmed on the hardware.

Boot the ISO (below), open **TERMINAL**, and run:

```bash
sudo moonlightos-hardware-report
```

The report runs the four section 0 commands, checks the results, adds the
hardware detection summary, and saves a copy under `/var/log/moonlightos/`.
You can also run them by hand:

```bash
sudo dmidecode -s system-product-name
sudo dmidecode -s system-serial-number
lspci -nn | grep -iE 'vga|3d|net|audio'
lsusb
```

Expected:

| Check | Expected result |
|---|---|
| Serial number | `DCPM5026FQPG` |
| Model | `iMac14,2` (27-inch; GT 755M, GTX 775M, or GTX 780M) or `iMac14,3` (21.5-inch; GT 750M) |
| GPU | an NVIDIA `[10de:....]` VGA or 3D controller |
| Wi-Fi | Broadcom BCM4360 `[14e4:43a0]` |
| Ethernet | Broadcom BCM57766 `[14e4:1682]` |
| Audio | Intel HDA controller; codec Cirrus Logic CS4208 |

If the model is `iMac14,1`, the machine is the 21.5-inch Intel Iris Pro model
with no NVIDIA GPU. The general ISO drives Iris Pro with `i915` and the `i965`
VA-API driver, but nothing in this document applies to it. Stop as well if
anything else in the table differs, and report it before relying on this
document.

## How the general ISO handles the iMac

| Component | Behavior |
|---|---|
| GPU: NVIDIA Kepler | In-kernel `nouveau` with Mesa. The general ISO contains no proprietary NVIDIA driver (its build fails if one appears). Kepler's last proprietary branch (470) has no GBM, which wlroots/Cage require, and the 550 driver on the NVIDIA ISO does not support Kepler. KMS stays on: never add `nomodeset`. |
| Video decode | Kepler has no HEVC decoder, and nouveau's H.264 decoder needs firmware that cannot be redistributed. `moonlightos-hwdetect` records the nouveau display driver, and Moonlight starts with software H.264 (see [Moonlight defaults](#moonlight-defaults)). |
| CPU: Haswell quad-core i5/i7 | Debian kernel defaults; `intel-microcode`. |
| Panel: 2560x1440 or 1920x1080 | Cage starts on the panel's preferred (native) mode. Settings → Display marks it `(NATIVE)`. |
| Wi-Fi: Broadcom BCM4360 | `broadcom-sta-dkms` (`wl`), built with DKMS for the image kernel during the build and checked in the final squashfs. At boot, `moonlightos-hwdetect` finds the BCM4360 on `wl`'s supported list and blacklists the open Broadcom drivers (`b43`, `b43legacy`, `b44`, `bcma`, `ssb`, `brcmsmac`, `brcm80211`) for that boot only. |
| Ethernet: Broadcom BCM57766 | `tg3` with `tigon/tg357766.bin` from `firmware-misc-nonfree` (checked at build time). |
| Audio: Cirrus Logic CS4208 | `snd-hda-intel` (codec fixups are automatic); `firmware-cirrus` is included. |
| Bluetooth: Broadcom | `btusb`; managed in Settings → Bluetooth. |
| Apple keyboard | `options hid_apple fnmode=2` on every machine: F1–F12 act as function keys (F12 opens the on-screen keyboard); hold Fn for media keys. |
| Sensors | `moonlightos-hwdetect` loads `applesmc` when the DMI vendor is Apple; `lm-sensors` output appears in System Diagnostics. |
| Firmware | The general ISO's curated list (see [HARDWARE.md](HARDWARE.md)). |

Run `/usr/libexec/moonlightos-hwdetect report` to see the decisions for the
current boot.

## Boot steps

1. Write the ISO to a USB drive in raw/DD mode (for example
   `sudo dd if=moonlightos-<version>-amd64.iso of=/dev/sdX bs=4M conv=fsync`,
   Rufus in DD mode, or balenaEtcher). The macOS `dd` commands and the
   `SHA256SUMS` check are in [INSTALL.md](INSTALL.md).
2. Plug the drive into a rear USB port, connect Ethernet if available, and
   power the iMac on while holding **Option (⌥)**.
3. In the Apple Startup Manager, choose the yellow **EFI Boot** entry. The
   2013 Apple firmware has no UEFI Secure Boot, so nothing needs to be disabled.
4. GRUB starts **Start MoonlightOS** after three seconds (press an arrow key on
   the keyboard to stop the countdown and choose another entry). The launcher
   appears at the panel's native resolution.
5. If the screen stays black, reboot and pick **Start MoonlightOS (No
   Persistence)**, which ignores anything saved on a persistence stick. Do not
   add `nomodeset`: Cage needs KMS. A black screen leaves no shell to collect
   logs with (see
   [TROUBLESHOOTING.md](TROUBLESHOOTING.md#the-screen-stays-black-or-the-launcher-never-appears));
   once the launcher does appear, Settings → Generate Support File collects
   `/var/log/moonlightos` and the journal.

Installing to the internal disk (**Install MoonlightOS**) erases macOS. Late
2013 iMacs may have a Fusion Drive (separate SSD and HDD); choose the target disk
carefully in the installer.

## Wi-Fi

Open Settings → Setup Wizard → Network, or the hidden **NETWORK SETUP**
application, and join the network. Check the driver in System Diagnostics
(`wlp…s0 driver: wl`) or with `lsmod | grep '^wl '`.

On an installed system, a kernel update rebuilds `wl.ko` through DKMS; keep
`linux-headers-amd64`, `dkms`, and `broadcom-sta-dkms` installed. The build
removes the DKMS module-signing key it generates, so the ISO carries no private
key; an installed system generates its own on the next rebuild. Because the
module is unsigned, `wl` loads only with Secure Boot off, which is always the
case on this Apple firmware.

## Moonlight defaults

`/var/lib/moonlightos/config.ini` starts with `codec = auto` and
`decoder = auto` on every machine. When `moonlightos-hwdetect` reports nouveau
as the display driver and both settings are still `auto`, the launcher starts
Moonlight with `--video-codec H.264 --video-decoder software`, and on first
launch seeds Moonlight's own settings file with 1920x1080, 60 FPS, H.264, and
software decoding. After that, changes made in Moonlight's settings persist;
1440p stays selectable there (on the 27-inch panel it is the native
resolution). Setting `codec` or `decoder` in `config.ini` overrides the hint.

## Known limitations

- **Software-only decoding.** Kepler cannot decode HEVC or AV1, and nouveau's
  H.264 decoder needs non-redistributable NVIDIA firmware, so Moonlight decodes
  H.264 on the CPU. 1080p60 is the target; 1440p60 may drop frames on the i5.
- **nouveau clocks.** nouveau does not reclock Kepler automatically; the GPU
  runs at its boot clocks. Compositing a 2560x1440 panel works, but GPU-heavy
  work is slow. No proprietary driver is an option (no GBM on 470, no Kepler
  support in 550).
- **Wi-Fi** uses Broadcom's proprietary `wl` driver built with DKMS. It needs
  Secure Boot off (always true on this firmware).
- Sleep/resume, display brightness control, fan behavior under sustained load,
  headphone-jack switching, and the FaceTime HD camera are untested.
- Nothing in this document has been verified on the physical iMac yet; see the
  hardware checklist in [TESTING.md](TESTING.md#imac-late-2013-hardware-checklist).
